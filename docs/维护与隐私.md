# 后续维护与发布

开发目录、待公开目录和私有配置分开。只按明确文件清单准备源码与下载附件，不同步整个工作环境、游戏目录、旧ZIP、个人配置和日志。

每轮固定顺序：确认EXE/资源基线→独立分支或候选开发→只验证受影响范围→更新功能/知识/地图文档→分别检查源码与下载附件隐私→固定文件清单、提交和SHA256→发布新标签→核对远端下载哈希并回写状态。

源码检查通过不能替代安装包检查。代码中没有密钥不等于图片元数据、可执行程序、Git历史和压缩包中没有；未扫描项必须记录，不能默认为通过。源码提交、离线验证、用户实机反馈和正式发布分别标记。用户明确暂停上传时只维护本地候选。

只读初筛工具为`补丁工作仓库/脚本/audit_publication_privacy_v1.py`：

```powershell
py -3 补丁工作仓库/脚本/audit_publication_privacy_v1.py --root . --out ../private-audit
```

私有报告放公开仓库外，不提交。报告仅记录位置、类型和行号，不打印凭据值。对邮箱、账号、个人路径和疑似凭据逐项判断，保留第三方合法署名；对真密钥更换/撤销后处理历史，不承诺删掉文件能收回已经公开的副本。

扫描器仅作有限规则初筛，不是无泄漏保证；原始二进制、图像文字/元数据、数据库、Git历史和多层压缩需另查。`.gitignore`不会清除已提交内容。首次建立干净Git历史，后续检查实际暂存差异和待推送提交。

文件变化后重查受影响项和最终附件；同一输入哈希、工具版本和检查范围的既有证据可复用。正式附件固定之后不在上传步骤重新构建，发新版本而不暗中替换同名旧附件。
